# User Story Template

## Story

**As a** [user / role]  
**I want** [capability]  
**So that** [business outcome]

## Business Context

Why is this needed?

## Acceptance Criteria

Use clear, testable outcomes.

- Given...
- When...
- Then...

Example:

**Given** I am an authorised user  
**When** I submit an approved request  
**Then** the request is processed and a confirmation is displayed

## Non-Functional Requirements

Consider:

- security;
- performance;
- availability;
- privacy;
- accessibility;
- logging;
- auditability.

## Dependencies

- systems;
- vendors;
- APIs;
- data;
- other stories.

## Risks / Assumptions

Document material risks or assumptions.

## Definition of Done

- acceptance criteria met;
- testing complete;
- documentation updated;
- security requirements addressed;
- operational readiness confirmed where applicable.
