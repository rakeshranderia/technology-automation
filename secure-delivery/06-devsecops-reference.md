# 06 — DevSecOps Reference

## Simple Explanation

DevSecOps integrates security into delivery rather than treating it as a late-stage gate.

A practical pattern is:

**Design → Build → Scan → Test → Review → Release → Monitor**

## Practical Controls

- secure coding expectations
- dependency scanning
- secrets scanning
- static analysis
- infrastructure/configuration validation
- peer review
- automated testing
- environment separation
- approval controls
- security logging
- vulnerability remediation

## Principle

Security should be involved early enough to influence design, not only late enough to reject a release.

## Caveat

DevSecOps is not a product. It is a delivery model supported by tools, ownership and repeatable controls.
