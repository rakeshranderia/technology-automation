# Secure Delivery

This module covers practical delivery controls across software change, source control, environments, testing, release and transition to operations.

The focus is not on prescribing a specific DevOps platform. It is on making delivery repeatable, reviewable and supportable.

## Design Pattern

**Requirement → Build → Review → Test → Approve → Release → Operate → Evidence**

A useful delivery control should answer:

- What changed?
- Who changed it?
- Where was it tested?
- Who approved it?
- How was it released?
- What evidence remains?
- Who owns it once it is live?

The material is grounded in practical experience across:

- BAU transition;

## Purpose

This is a practical secure-delivery reference.

It is not a complete software-engineering methodology, DevSecOps maturity model or claim that every organisation should use the same tooling.
