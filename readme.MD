# Technology Automation

Practical automation, scripting and technical-control examples across IT operations, Microsoft 365, identity and security.

The emphasis is not on complex software development. It is on using small, understandable automation patterns to make operational and control activities more repeatable, visible and auditable.

## Design approach

**Business problem → Automation → Control → Evidence → Outcome**

A script is not the control owner. Automation reduces repetitive effort; evidence makes the activity observable; people still own the decision.

## Control alignment

Some modules reference ISO 27001:2022 or other control frameworks where there is a defensible connection. These references describe control intent; running a script or following an example does not by itself create compliance or certification.

## Use of examples

All examples are sanitised portfolio material and should be reviewed, tested and adapted before production use.
