# Technology Automation

Practical automation, scripting and technical-control examples across IT operations, Microsoft 365, identity and security.

The focus is on turning real operational problems into repeatable technical patterns that support governance, reliability and evidence.

## Design principles

**Business problem → Automation → Control → Evidence → Outcome**

**Policy says what must happen.  
A technical control makes the expected action repeatable.  
Evidence shows that it happened.**

Automation does not replace control ownership or judgement. It helps make expected actions repeatable, observable and easier to evidence.

## Current IAM focus

The Identity & Access Management module currently includes practical patterns for:

- making access visible;
- making deprovisioning repeatable;
- reducing orphaned permissions;
- preserving an evidence trail;
- supporting control owners with automation rather than replacing judgement.

Examples include:

- user offboarding;
- Active Directory and Microsoft 365 entitlement removal;
- Exchange and collaboration cleanup;
- local file-share deprovisioning;
- ACL export and access visibility;
- progress reporting;
- completion evidence and notification.

## Purpose

This repository is a practical technology-automation library.

It is not an ISO 27001 implementation guide, certification claim or product catalogue. Control mappings and examples are illustrative and are intended to show how governance requirements can be translated into practical operational patterns.
