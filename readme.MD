# Technology Automation

Practical automation, scripting and technical-control examples across IT operations, Microsoft 365, identity and security.

The focus is on turning real operational problems into repeatable technical patterns that support governance, reliability and evidence.

## Design principle

**Business problem → Automation → Control → Evidence → Outcome**

Automation does not replace control ownership or judgement. It helps make expected actions repeatable, observable and easier to evidence.

## Current areas

### Identity & Access Management
Access visibility, offboarding, permissions review and evidence.

See: [`iam/README.md`](iam/README.md)

### Microsoft 365
Administration, reporting, Graph and operational automation.

### Operations
Infrastructure and service-management automation.

### Security
Technical-control and security-operations examples.

### Playground
Experiments, learning and examples that do not yet warrant formal control framing.

## Purpose

This repository is a practical technology-automation library, not a compliance implementation guide or certification claim.
